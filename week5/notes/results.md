## 課題1：Transaction

### 実験前の予想

```text
ROLLBACK後の田中の残高：1000
ROLLBACK後の佐藤の残高：1000
COMMIT後の田中の残高：800
COMMIT後の佐藤の残高：1200
```

### 実際の結果

```text
ROLLBACK後の田中の残高：1000
ROLLBACK後の佐藤の残高：1000
COMMIT後の田中の残高：800
COMMIT後の佐藤の残高：1200
```

### 分かったこと

```text
COMMITとは：更新の確定
ROLLBACKとは：更新を取り消して、更新前のデータに戻すこと
複数の更新をTransactionでまとめる理由：関連する更新の一部だけが反映されるのを防ぎ、
すべて成功またはすべて失敗にしてデータの整合性を保つため
```

## 課題2：Lost Update

### 実験前の予想

```text
A：1000円から100円引く → 予想残高：900
B：1000円から200円引く → 予想残高：800
両方を実行した最終残高の予想：800
```

### 実際の結果

```text
Aが書き込んだ値：900
Bが書き込んだ値：800
データベースの最終残高：800
消えてしまった更新：A
```

### 分かったこと

```text
Lost Updateが起きた理由：複数の処理が同じ古い値を読み、それぞれ計算した結果で上書きしたこと
危険になりそうな実務上の場面：残高、在庫数、予約枠、ポイント数などを複数ユーザーが同時に更新する場面
```

## 課題3：Row Lock

### 実験前の予想

```text
Aが行をロックしている間、Bはどうなる？：Bはそのデータを更新できない
AがCOMMITした後、Bはどうなる？：Bはcommit後のデータを読む
```

### 実際の結果

```text
AがFOR UPDATEを実行した結果：1000
BでFOR UPDATEを実行した直後の状態：待機、何も表示されない
AがCOMMITした後のBの状態：Aの作業後のデータが表示される
Bが読み取った残高：800
```

### 分かったこと

```text
SELECT ... FOR UPDATEの役割：更新予定のデータをロックし、他方からの更新を防ぐ
ロックが解除されるタイミング：コミット後
Lost Updateを防げる理由：FOR UPDATEでの何らかの更新作業を待機し、作業終了後の値を読むことができるから
```

## 課題4：Isolation Level

### 実験前の予想

```text
READ COMMITTEDでAが2回目に読む値：Bの更新後の値
REPEATABLE READでAが2回目に読む値：1回目に読んだ値
AがCOMMITした後に読む値：Bの更新後の値
```

### 実際の結果

| Isolation Level | Aの1回目 | BがCOMMITした値 | Aの2回目 | AのCOMMIT後 |
| --------------- | -------: | --------------: | -------: | ----------: |
| READ COMMITTED  |     1000 |             800 |      800 |         800 |
| REPEATABLE READ |     1000 |             800 |     1000 |         800 |

### 分かったこと

```text
READ COMMITTEDで値が変わった理由：他のtransactionの値はcommitされれば、閲覧可能
REPEATABLE READで値が変わらなかった理由：Transaction内で最初に確定したスナップショットを使い続けるため。
他のTransactionがCOMMITしても、同じTransaction内からはその変更が見えない。
スナップショットとは：ある時点で、そのTransactionから見えるデータの状態。
データ全体をコピーしたものではなく、どのデータ変更を見せるかを判断するための基準。
```

## 課題5：ACID

```text
Atomicityが守ったこと：変更の確定と取り消しを行えること
Consistencyが守ったこと：DBのルールを守らせること
Isolationが守ったこと：同時処理による変更の矛盾を起こさせない
Durabilityが守ったこと：変更後のデータの永続化
CHECK制約が拒否した更新：stockがマイナスになる更新
COMMIT後に残ったデータ：購入者Aのみによる購入履歴
```

## 課題6：最後の1個

```text
AのUPDATE結果（更新行数）：1
BのUPDATE結果（更新行数）：0
最終在庫数：0
作成された注文数：1
2人とも購入成功にならなかった理由：Bの注文はAの後に実行されるためstock 0を下回る注文は拒否される
```
